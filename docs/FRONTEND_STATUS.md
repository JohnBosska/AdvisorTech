# Статус frontend и требования к backend

Обновлено: 2 ноября 2026. Код: [`frontend/`](../frontend). Документы: [архитектура](../FRONTEND_ARCHITECTURE.md),

## Реально работает (backend)

| Экран | Что делает |
|---|---|
| `/login`, `/register`, `/verify` | Email-регистрация, код (8 цифр, повтор через 60 с), вход. `403` при входе ведёт на подтверждение |
| `/onboarding`, шаги 1–3 | Создаёт организацию (`POST /organizations`) и черновик подключения 1С (`POST .../connections`) |
| `/app/integrations`, блок «Ваши подключения» | Список и создание подключений; роли `OWNER`/`IT_ADMIN` |
| `/app/subscription` | Статус подписки из API; цены не показываются |
| `/app/ai-analyst` (AI-аналитик) | Чат и база знаний организации: документы `.txt`/`.md`, ответы только по ним со ссылками на источники; без ключа модели чат отвечает «не подключён» |
| `/app/settings` | Профиль (`/auth/me`) и организация |

## Демо (данные и поведение имитируются, везде есть «Демо-данные»)

Обзор, аналитика товарных групп, запасы и склады, логистика, 
финансовая отчётность (демо-проводки и баланс), история синхронизаций и качество данных, инфраструктура PostgreSQL,
отчёты (статусы симулируются, скачивается демо-CSV), шаги 4–8 мастера, форма «Запросить подключение».
Данные: `frontend/src/mocks/`. Для реальной выгрузки Excel нужен серверный генератор.

## Лендинг

Компоновка и анимации повторяют эскиз neon.com (PDF): светлая страница с тёмной hero-панелью (анимированные вертикальные «эквалайзер»-полосы, ноутбук с мозгом справа), метки-стрелки и крупные моно-цифры 01/02/03, двухтонные фразы, ряд из 4 колонок с анимированными мини-карточками, веер карточек-«окон», схема архитектуры с тёмными выносками и пиксельными иконками, график с переключателем режимов, колонки со стеком, halftone-иконки тарифа. Кабинет и страницы входа остаются тёмными. Тексты и иллюстрации не содержат выдуманных клиентов, цифр и цен.

Герой — ваш прототип `brain-laptop`, перенесённый в React Three Fiber (`components/3d/`): клик, касание, Enter/Space
рассыпают символы и собирают мозг; пауза вне экрана; без WebGL и при `prefers-reduced-motion` — статичная/спокойная версия.

## Решения

- CORS нет: dev использует прокси Vite (`/api`); в проде отдавать SPA и API с одного origin либо добавить CORS.
- Токен в `sessionStorage` (нет refresh/logout/cookie в backend), сбрасывается при любом `401`.
- Один менеджер пакетов — npm, один lock-файл. Playwright не подключён (браузеры не ставились).
- Основной chunk ~210 КБ gzip; Three.js (~250 КБ gzip) загружается только на лендинге.

## Что нужно от backend (по приоритету)

1. Refresh-токен в HttpOnly-cookie, `POST /auth/refresh`, `POST /auth/logout`; CORS-настройка.
2. Connector Registry/Gateway: регистрация агента, статусы подключения, запуск и история синхронизаций (BR-005–008, BR-022).
3. Ingestion и Data Warehouse: пакеты, Raw/Staging/Core/Marts, отдельная PostgreSQL на клиента (BR-009–011, BR-010).
4. Data Quality: статусы `VALIDATED`/`PARTIALLY_VALIDATED`/`REQUIRES_ATTENTION`/`FAILED` по сущностям (BR-012, BR-020).
5. Analytics API + KPI Dictionary: товарные группы, запасы, логистика с периодом, сравнением и происхождением (BR-013–015).
6. Financial Reporting: сопоставление счетов, версии правил, отчёты и drill-down (BR-016) — после проверки бухгалтером.
7. AI: инструменты SQL/Python поверх Data Warehouse и структура ответа из brief §5.5 (BR-017, BR-018). RAG по документам организации (pgvector + полнотекстовый поиск) и чат уже работают, см. ниже.
8. Reports: серверная генерация `.xlsx` (openpyxl/XlsxWriter), статусы `queued/processing/ready/failed/expired` (BR-019).
9. Подписки: тарифы, лимиты, биллинг — после решения владельца продукта.
10. Приглашение сотрудников и смена ролей (роли уже есть в модели).

## Известные ограничения

- Playwright E2E и визуальные регрессии не настроены; проверка — vitest (16 тестов), lint, typecheck, сборка и ручной прогон в браузере.
- Telegram-вход в UI не реализован (бэкенд поддерживает).
- Радио-выбор «Используете ли вы 1С?» в мастере и мобильная вёрстка таблиц проверены поверхностно.
